### 2. Qualified compiler distribution and wrapper

Consume the existing standalone JAR built independently from exact core source, with its digest, source revision, compiler identity, qualified Java version, reproducible build instructions and redistributable dependency notices. The packaging owner supplies the candidate and measured cold-start evidence. A demo clone must not depend on a sibling checkout or a new compiler implementation. Java is a documented compile-only prerequisite; missing Java or an invalid compiler distribution disables compilation with a safe explanation while native tasks, stored selections and the Node runtime still start and work.

The trusted server configuration chooses the Java executable; request fields cannot choose executables, paths, JVM options, model, profile, compiler identity, host bindings or artifact bytes. Invoke a direct argument array with `shell:false`: bounded Java heap, exact pinned JAR, private fixed source/model filenames and exactly `--profile=keir-read/2`. Use a fresh private temporary job directory and host-owned trusted model bytes. Use a minimal platform environment; exclude JVM option injection variables, classpath and unrelated credentials. Do not modify global Java, PATH or persistent environment settings.

Compiler limits: one active child per application, no queue; source at most 65,536 UTF-8 bytes; artifact/stdout at most 1,048,576 bytes; stderr at most 16,384 bytes; proposed heap ceiling 256 MiB and wall deadline 10 seconds, subject to cold-start qualification. Stream and count bytes before concatenation. Abort on timeout, overflow, cancellation or request disconnect, then terminate and await the child's close/reaping before releasing the slot or removing its directory. The standalone CLI spawns no descendants. Drain bounded output and handle spawn/error/exit races exactly once. If normal termination does not settle, use a bounded direct-child termination escalation; never signal unrelated processes. Do not describe these controls as an OS sandbox or hard whole-process memory containment.

Return fixed host messages and bounded validated compiler diagnostic codes/structural locations, never arbitrary stderr, exception text, source fragments or private machine paths. Empty, malformed, oversized or nonzero-exit output cannot produce an executable revision. Preserve stdout as bytes. Independently hash and prepare successful output against trusted model/compiler/environment/consumer pins before persistence. Store the digest of exact submitted source bytes separately from the compiler artifact's canonical decoded-source digest; do not build another YAML parser to imitate compiler semantics.

### 3. Immutable storage and compatibility

Add schema 3 as a transactionally applied additive migration. Keep existing revision, evidence, approval, selection and history IDs, operator provenance, prepared identities and original six-case suite digests unchanged. Add an owner-qualified authored-content table referencing the existing revision/owner pair. It stores bounded exact source bytes, compiled artifact bytes, independent suite bytes and a bounded display label. Existing non-null template IDs remain valid; an internal authored discriminator is selected only by the host's authoring operation, never admitted through the prepared-template endpoint. Resolution requires the authored content row and exact pins, rather than treating that discriminator as a prepared program.

Keep raw-source, artifact, model, compiler canonical-source metadata, environment, profile, hook, consumer, package/adapter identity and authored-suite/host-fixture-policy identities bound to the immutable revision. Hashes detect mismatches but do not grant ownership or approval. All lookups use the server-held owner plus exact revision. Check stored bytes and dependency compatibility before execution/eligibility; invalid content makes advice unavailable without disabling native CRUD.

Limit newly authored stored revisions to 32 per owner, including historical/approved/active authored revisions. Check before expensive compilation and again in the committing transaction. Reject a new revision at capacity with a clear message; never silently delete active, approved, historical or in-flight snapshots. Leave prepared revision retention unchanged. Any later archive/delete policy is separate scope.

A successful source or suite edit creates a new immutable revision and advances the draft version by compare-and-swap. Compilation happens outside SQLite transactions; reauthorize and recheck owner/current draft version, quota and admitted content inside the synchronous final transaction. Failed compile, cancellation or stale completion leaves the existing draft, active selection and approvals untouched. Editing never mutates or silently activates the old approved snapshot.

Update verified backup/reset table inclusion and dependency deletion order for the new table. Exercise v1-to-latest and populated v2-to-v3, failed migration rollback, repeated open, backup verification and reset with synthetic data. Never migrate/reset a user's running preview during this task.

### 4. Independent authored suites and exact evidence

The manager-approved minimum is 1–8 unique-ID cases, each at most 65,536 bytes, with at most 131,072 bytes in the canonical aggregate suite. Accept bounded case JSON as data preserving the original scenario bytes; the actual strict read-simulation parser remains authoritative for duplicate fields, depth, DCM types and supported shapes. Invalid scenarios cannot produce eligible evidence. Each case independently supplies ordered stubs, exact expected calls, native outcome and allowed consumer receipt. Do not infer expectations from compiled source, observed output, template ID or a previous report.

Use the existing simulator against exact immutable authored bytes. Respect native limits, including at most four stubs/calls per case. Do not assume a step named source, a single read, a fixed error path, completed tasks returning Done, or a missing-task rejection for a program that performs no read. Derive the set of required host-binding names from the independently admitted artifact; supply only host-controlled values: empty bindings for no-call artifacts and the current actor binding when tasks.get is used. Apply the same rule to live invocation. Cases cannot select host authority, callbacks, scope, model or bindings.

Pin authored suite bytes, policy/fixture version and simulator dependencies in suite identity. Run with the existing owner/global simulation concurrency of one/two and checked one-second case deadlines. Keep the 128 KiB persisted evidence and 256 KiB lifecycle-state response limits; reject complete oversized evidence rather than truncate it into eligibility. Every case must PASS with matching owner/revision/dependencies/suite, report order/count, expected data and receipt before approval is eligible. Preserve independent approved-run and latest-run identities. Source or suite changes create a new revision requiring fresh passing evidence and explicit approval; the active snapshot remains pinned until a separate Use or restore operation.

A finite independent suite is evidence of its listed cases, not proof of all possible behavior. Mandatory host authorization, native-error, owner/session/generation, resource and cache regression coverage is separate from the customer's minimum suite. Capability-specific cases apply to programs that call that capability; do not impose artificial read obligations on valid constant programs. The acceptance fixture includes a successful displayed outcome plus a genuine incorrect expectation that blocks approval, then independently corrected expectations.

Use an LRU of at most 16 prepared owner/revision/dependency entries. Preparation and failure paths must not grow an unbounded cache. An active invocation retains its own immutable prepared reference; cache eviction alone does not invalidate that invocation or free its snapshot. Continue checking the actual selected revision, generation, eligibility and session before dispatch, after awaited native reads and before display. Preserve the eight-active-invocation limit, checked deadlines, host task projection and honest NOT_DISPLAYED fallback. An away-and-back selection change must still invalidate a previously captured invocation even when artifact bytes match.
