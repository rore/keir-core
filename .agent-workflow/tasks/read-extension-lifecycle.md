## Lifecycle contract

The architect's bounded consultation and explicit activation/rollback clarification support Elevated risk and Moderate complexity. The designer mapped this real read-only flow to the accepted baseline. Independent technical plan review approved the frozen contract and verification. No implementation or new tests have run yet.

| Operation | Required server behavior |
| --- | --- |
| State/catalog | Return only the current session owner's hook state, bounded curated template list, draft/evidence/approval eligibility, active generation and eligible previously active choices. Never accept owner, grants, callbacks, raw bundles or approval/evidence claims from the client. |
| Load candidate | Accept a server-listed template ID and expected draft version; create an immutable owner/hook revision and advance its current-draft pointer/version. Maya can choose the packaged alternate program through her own records. Source filenames are descriptive, not authority. Store exact source/artifact/model/profile/compiler/environment/package/adapter/consumer references and pins. |
| Simulate | Capture the immutable revision/dependencies, run the actual packaged simulator outside the transaction against a fixed code-selected suite and independent expectations, then recheck current session/ownership/draft/dependencies before persisting eligible evidence. Include complete suite/scenario/expectation/fixture/simulator identities and bounded reports. No real task/service I/O or client-selected authority. |
| Approve | An explicit user action names the exact revision, reviewed evidence ID and expected current draft version. In one transaction, recheck session/owner/hook/current draft, dependencies and complete passing evidence. Persist actual approver and evidence identity. Current active advice stays unchanged. |
| Activate | Require exact current draft revision/version, its eligible approval and expected selection generation, checked in the same transaction that selects it. New draft choice makes an old activation request stale even when active generation did not change. Return409 on conflict. |
| Disable | Recheck current session/owner/hook and expected generation; atomically select none and advance generation/history. Preserve approved history, native tasks and other users' choices. |
| Rollback | Name an exact previously active revision for the same owner/hook. Recheck actual activation history, current approval or operator provenance, dependencies and expected generation in the committing transaction. Never auto-pick latest, reactivate a never-active approval or silently bypass current eligibility. |

Every successful selection transition advances a monotonically increasing generation and records history atomically. Use existing synchronous BEGIN IMMEDIATE/commit/rollback; no await inside a SQLite transaction. Missing/foreign records fail without exposing another owner. Strict request shapes and bounded identifiers reuse existing API protections. Stale draft/evidence/selection mutations return409 and the client reloads authoritative state; uncertain mutation responses trigger readback before retry, not blind replay.

Migration bootstraps only once: preserve Maya and Leo's actual existing configured defaults with explicit legacy/operator provenance and exact pins; Sam remains unconfigured. Do not invent customer approvals or historical simulations. A migrated default is a restore target only because it was actually active and its pins/provenance still qualify. A later disable or rollback survives restart; missing state or invalid dependencies never trigger silent reseeding. Failed migration/backup preserves native data. New migration/reset behavior is tested only on isolated synthetic data, never the running demo database.

Advice captures owner/hook/generation/revision once and stays pinned to that revision. Recheck current session, native authority, approval/dependency validity and selection generation before dispatch and consumption; suppress stale advice if selection changes, including an away-and-back transition to the same artifact. Prepared immutable handles may be cached; neither cache object identity nor browser state owns selection. Keep native task CRUD usable when advice is off or invalid.

Customer approval, legacy operator configuration and simulation PASS are separate facts. Trusted server/SQLite records plus current host policy establish authority; hashes alone do not. Preserve fail-closed checks for malformed references, stale identities and browser forgery without claiming protection against someone who controls the local server/database and trust material.
