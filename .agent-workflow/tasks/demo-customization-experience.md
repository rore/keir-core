## Concrete design and interaction brief

| Surface | Required implementation |
| --- | --- |
| Host identity | Daymark is the working demo-app name on sign-in, rail, narrow masthead and browser title. Use a small original page/check mark; Powered by Keir is secondary attribution. Keep package, cookie, model and consumer identifiers intact. Remove repeated slogans and oversized editorial hierarchy from working screens. |
| Navigation | Persistent Tasks and Customizations destinations, then projects; selecting a project selects Tasks. Keep the current owner visible. Narrow screens have an accessible destination/project menu independent of the hidden rail. Local view state is sufficient; do not add a router dependency without a concrete need. |
| Customizations overview | Show one real Task advice item with the description Choose what you see when you check an open task, server-confirmed In use/Off/Unavailable and a separate current draft/approved-awaiting-use state. Set up/Edit/Continue draft opens the same Studio. Prepared outcomes are alternatives within that item; do not invent a gallery, empty New action or unsupported AI abilities. Fetch guarded owner-scoped state and refresh on return; presentation booleans never authorize transitions. |
| Studio destination | Same app shell, Customizations selected, breadcrumb Customizations / Task advice and a distinct Studio workspace bar. General entry returns to overview/invoker focus. Retain a quiet Manage task advice contextual shortcut from task details to the same Studio, preserving an exact detail origin and existing unsaved-edit journey; ordinary navigation is the primary entry. Never assume every entry came from a task. |
| Native return | Preserve task/project, unsaved title/notes, quick-add/project form state and intended scroll position. Separate navigation suspension from native discard; an inactive native modal must not trap focus or leave a backdrop in Studio. Restore detail only for the current owner and still-accessible task, with focus at the invoking control. User switch discards old-owner return/draft/response context. |
| Conversation/canvas | Ask one concrete question about checking an open task; real catalog choices are replies. One advice sheet shows Open task In use -> Proposed and Done for completed tasks under either prepared rule; an off/unavailable current selection must show that state rather than invent a current Done result. The rule applies to the owner's tasks across projects, not an implicit selected-project filter. Contextual views show actual samples or exact review. Use one primary next action; saved runs, technical identities, reload and eligible disable/restore are secondary, while Retry is visible on errors. Explicit Approve and subsequent Use remain separate. Historical evidence remains read-only; incoming results must not displace a view the person is reading. Preserve the real saved-task check after activation. |
| Visual system | Common sans-serif hierarchy, 4/8/16/24 spacing, readable 15-16px body, supporting13px, regular36-40px controls/larger mobile targets, shared focus/borders/radii/state vocabulary. Host uses restrained white/mineral/ink with blue-black actions. Studio adds a named workspace, white conversation and ivory advice sheet on slate, with ochre proposed-value margin plus text. No second product wordmark or decorative AI motif. |
| Desktop scrolling | Logged-in shell uses bounded100dvh; rail/header stay outside main content scroller. Long projects scroll only in their rail section. Main tasks/overview scroll independently. Studio fills remaining space with min-height/min-width0 grid/flex ancestors; transcript/canvas scroll separately, composer/splitter remain outside them and overscroll is contained. Do not globally disable welcome scrolling. |
| Narrow/short layout | Switch before panes become cramped, including short/zoomed views. Narrow Studio uses Conversation / Preview views of the same state with explicit sample-results jump/back, retained pane positions and unsent composer. Keep primary/review/restore controls reachable without horizontal overflow or a long nested stack. |
| Focus/accessibility | Focus the destination heading on entry and actual invoker on return; one visible main/heading structure, current navigation state, native-dialog Escape/return, keyboard splitter limits based on usable widths, visible focus and meaningful single loading/result/error announcements. User-driven reading/scrolling is not displaced by arrivals. |
