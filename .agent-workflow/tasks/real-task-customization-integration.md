## Accepted integration decisions

Use a small release bundle containing the canonical execution-build manifest, actual SQLite/runtime qualification report and separately reviewed host approval selecting their exact identities and supported environment. Hash actual installed execution-relevant code, adapters/authority/dispatcher/lifecycle, model/consumer/schema, core/compiler packages and dependency identity; exclude report/approval files to avoid cycles. Startup verifies the installed bytes and exact Node/SQLite/platform/architecture/schema/PRAGMA tuple before real binding. The supported reviewed release needs no customer qualification workflow. Modified or unsupported execution builds retain native CRUD while real effects remain unavailable; isolated operator qualification produces a report but never approves itself. Reuse existing provenance and setup paths, with no registry, remote service, Studio wizard or generic certification subsystem. Reports state only measured local process-crash/restart guarantees, not arbitrary power-loss durability. The synchronous non-I/O currentness check uses an immutable verified deployment plus host-owned approval/revocation state, rather than scanning files inside a transaction. Persist revoked evidence before updating current state; old event revocation survives reenable and restart, with no silent upgrade to a new evidence revision.

Compile against an explicit allowlisted host definition: the source entrypoint and DCM/profile must match it, failed compilation leaves a new item unbound, and a bound item cannot silently switch hooks. Subsequent simulation/review uses its stored revision definition. Project discovery is an owner-scoped authoring read. For the first runtime integration, prepare a per-event binding outside the native transaction with one branded original key and a pure identity validator; retain that same key, Prepared handle and exact pins through the exclusive claim and invocation. Claim failure invokes nothing. Bound first dispatch handles PENDING only, with no GET-triggered work, STARTED replay or spinning on unavailable dependencies. Reconciliation preserves the immutable runtime outcome and records a separately dated native observation. Only confirmed native receipts support task links; source-authored result labels do not establish effects.

Retire legacy advice mutation/execution routes explicitly while retaining owner-authorized source/evidence/history, safe disable/delete/Stop, tombstones and original operation recovery/accounting. Recovery first resolves original receipts and payload mismatch checks, then reports retirement without creating a replacement conversation or resuming old work. New task programs receive fresh exact checks, approval and activation. Reuse the reviewed compact canvas and task-shaped examples, including two different customer project/title programs and later completion of a generated task. These decisions refine the accepted contract; exact implementation paths, tests, migration/preservation and rollout evidence still require the concrete plan and result gates.
