## Implementation

The candidate starts at `a79cebaf0fd942411e44d91c4b67b2e9ad22b881`. The new `--dense` phase reuses the existing direct-child supervisor and Windows JVM sampler. It adds a producer shape check and Java and Node serial workers. Existing default and soak workloads keep their inputs and checks.

## Evidence

The [qualification reference](../../conformance/resource-qualification/README.md#fully-evaluated-keir-2-membership-workload) contains the workload, command, sample and limits. Offline package preparation passed with tests skipped. The opt-in phase completed in 14.064 seconds. Both runtimes passed 100 warmups and 5,000 measured invocations with zero dispatch and identical artifact and outcome digests.

The artifact contains 473 nodes, depth 7 and 80 membership tests. The no-match input forces 1,280 element comparisons under the pinned linear implementations. These counts are derived from the checked structure and data, with no operator instrumentation.

The artifact SHA-256 is `79f5f443b1ffead00e1a89b3ac250d561ca0994f467b6afad88a142329aac3fe`. The full outcome SHA-256 is `ac36df3179b7953cd347710d5b13734104d7ff9322dfb9e54f5b302eafefa4dd`. The raw report SHA-256 is `1fb7f80a8bd6a3c15cc82bd6ece5d323e1f3696d4f3263cb310dcf05ab74c425`.

Java observed peak working set was 312,188,928 bytes and its final retained-heap span was 56,912 bytes. Node peak RSS was 94,392,320 bytes and its final retained-heap span was 3,968 bytes. Both passed the 8 MiB span threshold. Wrong-outcome checks stopped the workers before a successful warmup. The tiny-memory Node check stopped after one checked measured invocation.
