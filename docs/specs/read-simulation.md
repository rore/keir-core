# Compatibility reference: simulation reporting

`keir-read-simulation/1` runs a compiled catalog-bound read-only artifact through the native runtime against ordered data-only responses. It is an optional authoring tool; it does not change runtime admission or authorize live adapters.

The operator selects DCM/artifact bytes and independent SHA-256 pins, compiler identity, entrypoint and consumer. The host separately supplies scope, protected bindings, a deterministic deadline/clock, current authorizer, consumer callback and receipt allowlist. An optional host response check can enforce domain relationships. Cases cannot select these objects, functions, paths or modules. Each call creates a fresh binding/preparation; all adapters are constructed by the tooling in simulation mode. Unused WRITE catalog entries receive unreachable failing adapters; read admission still rejects WRITE execution.

A case is a closed JSON object with `format`, a bounded `id`, typed business `input`, ordered `stubs` and independent `expect`. Each stub has `step`, `capability`, `version`, business `args` and a declared `SUCCESS`, `BUSINESS_REJECTION` or `TRANSIENT_FAILURE` response. `expect` contains `calls` (the same call fields without response), a compact `outcome`, and `consumption`. The expected outcome is `{classification,result}` for `COMPLETED`, otherwise `{classification,error:{code,path}}`. Results are DCM-typed; error code/path compare privately to the original native diagnostic. Cases cannot contain trace, cause or other internal envelope fields. Missing-task rejection consumes an ordinary declared rejection stub. No protected arguments occur in case data. All fields, including unused stubs and expectations, are validated before invocation.

Dispatch must match the next stub's capability, version and business arguments, plus host protected bindings, without search, retry or fallback. Step identity is reconciled after settlement against ordered native `CALL_DISPATCHED` trace events because adapters do not receive step IDs. A separate run-local ledger retains adapter mismatches even when the runtime safely catches adapter exceptions. Missing, leftover, reordered and mismatching stubs fail independently of the expected native outcome.

Consumer receipts are closed `{ "status": "DISPLAYED", "code": "DONE" }` records with stable uppercase token codes, or `{ "status": "NOT_DISPLAYED" }`. The host provides 1–16 unique allowed receipts, validated at setup. Cases may expect only an allowed receipt. Consumer throws, malformed returns or unlisted receipts produce `CONSUMER_ERROR`; different valid receipts produce `MISMATCH`. The host must ensure callback purity, I/O safety and current-authorizer correctness. Simulation cannot certify those obligations.

Consumer and response-check callbacks are synchronous. Promise/future receipts and asynchronous response checks are unsupported. Current authorization keeps the native asynchronous interface. Setup validation precedes case validation; no authorizer or consumer is called for a malformed case.

The closed `keir-read-simulation-report/1` report contains `status`, trusted `identity`, bounded `mismatches`, and optionally allowlisted actual `consumption`. Once an actual outcome exists it also contains closed `native:{classification,code?}`, including on consumer failure. Status is `PASS`, `MISMATCH`, `INVALID_SCENARIO`, `SETUP_ERROR` or `CONSUMER_ERROR`. Identity contains the independent model/artifact digests, or is empty for setup failure. No case ID, capability/step names, arguments, result values, protected bindings, diagnostic paths, exception text or times are emitted. Comparison uses those values privately. Mismatch entries contain only fixed `stage`, fixed `code` and a one-based call `ordinal` (zero for non-call comparisons). Consumer failure takes precedence over mismatch status.

Native classifications are `COMPLETED`, `BUSINESS_REJECTION`, `FAILED`, `LIMIT_EXCEEDED`. Successful outcomes have no diagnostic code. The fixed public runtime-code allowlist is `AUTHORITY_DENIED`, `AUTHORITY_CHECK_FAILED`, `HOST_CONTEXT_INVALID`, `HOST_BINDING_INVALID`, `INPUT_INVALID`, `ADAPTER_EXCEPTION`, `ADAPTER_INVALID`, `ADAPTER_TRANSIENT`, `EXPRESSION_FAILED`, `BUDGET_EXCEEDED`. Every other code, including domain-controlled rejection codes, maps to `NATIVE_ERROR` in the report. The original code remains the private comparison input: two distinct business codes must still mismatch even if both public summaries use `NATIVE_ERROR`. A deliberately wrong Maya expectation reports actual native `COMPLETED`, `OUTCOME_MISMATCH`, and the actual allowed `DISPLAYED/PENDING` receipt without exposing raw result values.

Stages are `SETUP`, `SCENARIO`, `STUB`, `CALLS`, `OUTCOME`, `CONSUMER`. Codes are `SETUP_ERROR`, `INVALID_SCENARIO`, `MISSING_STUB`, `STUB_MISMATCH`, `EXTRA_STUB`, `TRACE_MISMATCH`, `CALLS_MISMATCH`, `OUTCOME_MISMATCH`, `CONSUMPTION_MISMATCH`, `CONSUMER_ERROR`. The ledger preserves the first eight entries. Omitted private details are never reconstructed from exception messages.

Limits: case UTF-8 bytes ≤65,536, JSON depth ≤16, stubs and expected calls ≤4 each, native trace events ≤64, mismatches ≤8, canonical report bytes ≤16,384. Duplicate keys, UTF-8 BOMs, malformed UTF-8, non-data values and undeclared fields fail closed. The tooling rejects BOMs for case and DCM setup bytes locally; native production parsers are unchanged. Data uses strings, booleans, nonnegative safe integers, arrays and records; null and fractional/negative metadata are unsupported. Native DCM/artifact/value/quota/deadline limits remain in force. JSON schemas describe decoded structure; native tooling also enforces byte/depth limits, DCM types, receipt membership and semantic relationships.

Node exposes `runReadSimulation(selection, fixture, caseBytes)` from `@keir/runtime-node/read-simulation`, returning a report object. The package root retains its existing runtime exports. Java exposes `ReadSimulation.run(Selection, Fixture, byte[])`, returning canonical report bytes. Java's outer settlement wait is bounded at three seconds; this is not synchronous preemption or host callback containment. Neither interface accepts an adapter map. Normal examples use deterministic host clocks and callbacks with no service I/O.

See [the runnable guide](../agents/read-simulation.md) and [structural schemas](../../schemas/read-2/). Effects, host certification, production services and authoring UI are outside this increment.
