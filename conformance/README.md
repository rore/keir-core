# Shared conformance

The [read-and-decide fixtures](read-and-decide/README.md) contain maintained source, DCM, deterministic Java compiler output and a 61-case shared corpus executed by both runtimes. The combined verifier compares full results, calls, authorization, traces and consumption and checks independent packaged hosts. The supplemental two-read fixture covers grant exhaustion and prepared reuse in both module suites. The [CEL qualification](cel-profile/README.md) records the earlier expression bridge. Both runtimes consume the same artifact bytes in the installed product CI check.

The [single-effect fixture](single-effect/README.md) adds a Java-compiled artifact and 25 shared simulation scenarios. Local combined verification compares full outcomes, traces, ordered calls and EVENT_REPORT consumption across Java, Node and both packaged hosts. Real-mode admission remains rejected; fake adapters establish no persistence or duplicate-safety guarantee.

The [generic-hook `/2` fixtures](generic-hooks/README.md) add six reference artifacts against two host-bound models, nine read/nineteen effect scenarios, authored nominal constants and generic task creation. The same combined verifier compiles every program twice and checks both runtimes and packaged hosts. `/1` fixtures remain unchanged. See [testing evidence](../docs/testing.md) for current local results and the separate CI status.

Compare typed values, exact call order and arguments, guard decisions, effects and termination classes. Keep compiler rejection tests, expression interoperability, runner conformance and real host adapter guarantees distinct.

The [testing plan](../docs/testing.md) identifies protected read-and-decide and single-effect obligations and their fast regression corpus. The CEL probe is qualification evidence with separate benchmarks, not the complete product contract. Conformance fixtures and independent expectations must evolve with accepted behavior, never be weakened to accommodate incomplete implementations.

The older design fixtures remain in [the baseline](../docs/internal/design-baseline/public/examples/). They are illustrative and have pending host certifications; they are not passing executable tests. Maintained fixtures here require explicit provenance and acceptance checks.
