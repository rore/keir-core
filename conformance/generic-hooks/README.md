# Shared generic-hook simulations

The read and effect directories hold one approved complete model each, three independently selected Java-compiled programs each, independent SHA-256 pins and hand-authored scenario expectations. The read variants select a second published READ or repeat the first READ. The effect variants change only the authored project or title, leaving the model, hook input and host context unchanged.

Scenario files contain bounded, closed, data-only records. `given.program` selects a fixed host file/pin mapping; it cannot name a path, module or model. The host supplies all authority, current authorization and original native key/event context. `tasks.create` receives only project/title business arguments; actor and native context travel separately. Stubs supply typed responses; ordered actual calls are reconciled against runtime dispatch evidence before complete outcome, trace, receipt and consumer comparisons. A runtime failure cannot hide a harness mismatch.

The corpus includes every approved fixture ID with its specified profile applicability: shared normal, invocation/call denial, wrong scope and read exception; effect-only zero ceiling, revocation after READ, invalid native key, wrong origin, lost WRITE response and completion-clock expiry. Additional cases cover no-op conditions, changed constants, business rejection, transient failure and unknown commit. Expectations are authored separately from compiler output and are never generated by a scenario runner.

Run the source Node batch with `node conformance/generic-hooks/run-node.mjs` and its tests with `node --test conformance/generic-hooks/node.test.mjs`. After building the Java packages and installing the reviewed Node package into the example host, run `node conformance/read-and-decide/verify.mjs` for the preserved legacy corpora plus generic parity and all packaged hosts. `node conformance/generic-hooks/verify.mjs` runs the generic portion alone.

Each lexical harness reserves finite model/prepared counts and byte budgets, one bind/prepare operation and two in-flight invocations, without a queue. It reserves the complete descriptor ceiling per model; four model reservations therefore bound aggregate descriptor bytes conservatively. Scenarios permit at most 1 MiB, 128 rows, 65,536 serialized bytes per row and four stubs/captured calls. Host capacity rejection uses `CAPACITY_EXCEEDED`, independently of runtime diagnostics. These controlled simulations do not establish real authorization, persistence, duplicate safety, remote cancellation or decoded-heap containment.
