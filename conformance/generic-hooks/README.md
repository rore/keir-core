# Generic capability simulation reference

Internal engineering reference: the current single-write behavior is exercised by this corpus. Exact selectors and wire identifiers are implementation details; see the [implementation reference](../../docs/internal/implementation-reference.md). A program-authored `CREATED` label in a zero-WRITE case carries no confirmed effect. The separate [qualified-write corpus](effect3/) checks the earlier admission protocol. See the [single-write verification record](../../docs/testing.md#effect4-verification) for local and hosted results.

Historical compatibility reference: `admission-cases.json` supplies 28 independently authored facts for fixed trusted host fixtures. Its driver and results cover that earlier protocol. In the current contract, permission denial inside an implementation is an attempted call and definite NONE only when no effect is established. Exceptions, timeout and response loss after dispatch remain UNKNOWN.

Run `node conformance/generic-hooks/real-effect.mjs` only for the earlier qualification protocol. Its deterministic fakes establish no SQLite atomicity, deployment qualification or live permission. The current single-write corpus has its own verification.

Run the current single-write corpus from the repository root with `node examples/node-host/generic.mjs conformance/generic-hooks/effect4`; the Java host uses `java -cp examples/java-host/target/keir-java-host-0.1.0-SNAPSHOT.jar dev.keir.examples.GenericHost conformance/generic-hooks/effect4`. After installing the packed Node runtime package in the example host, `node conformance/generic-hooks/bound-effect.mjs --installed` exercises the host-bound local/HTTP fixtures. The fixed corpus selects four programs (`main`, `zero`, `after-write-read`, `no-call`) and accepts at most 128 scenario rows. These are fixture-harness limits, not runtime API limits.

The read and effect directories hold one approved complete model each, three independently selected Java-compiled programs each, independent SHA-256 pins and hand-authored scenario expectations. The read variants select a second published READ or repeat the first READ. The effect variants change only the authored project or title, leaving the model, hook input and host context unchanged.

Scenario files contain bounded, closed, data-only records. `given.program` selects a fixed host file/pin mapping; it cannot name a path, module or model. The host supplies all authority, current authorization and original native key/event context. `tasks.create` receives only project/title business arguments; actor and native context travel separately. Stubs supply typed responses; ordered actual calls are reconciled against runtime dispatch evidence before complete outcome, trace, receipt and consumer comparisons. A runtime failure cannot hide a harness mismatch.

The corpus includes every approved fixture ID with its specified profile applicability: shared normal, invocation/call denial, wrong scope and read exception; effect-only zero ceiling, revocation after READ, invalid native key, wrong origin, lost WRITE response and completion-clock expiry. Additional cases cover no-op conditions, changed constants, business rejection, transient failure and unknown commit. Expectations are authored separately from compiler output and are never generated by a scenario runner.

Run the source Node batch with `node conformance/generic-hooks/run-node.mjs` and its tests with `node --test conformance/generic-hooks/node.test.mjs`. After building the Java packages and installing the reviewed Node package into the example host, run `node conformance/read-and-decide/verify.mjs` for the preserved legacy corpora plus generic parity and all packaged hosts. `node conformance/generic-hooks/verify.mjs` runs the generic portion alone.

The simulation harness for earlier contracts reserves finite model/prepared counts and byte budgets, one bind/prepare operation and two in-flight invocations, without a queue. It reserves the complete descriptor ceiling per model; four model reservations therefore bound aggregate descriptor bytes conservatively. Its scenarios permit at most 1 MiB, 128 rows, 65,536 serialized bytes per row and four stubs/captured calls. Host capacity rejection uses `CAPACITY_EXCEEDED`, independently of runtime diagnostics. These controlled simulations do not establish real authorization, persistence, duplicate safety, remote cancellation or decoded-heap containment. The current fixture row and program limits are listed separately above.
