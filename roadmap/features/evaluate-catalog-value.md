## Summary

Map realistic customer requests onto one proposed, frozen task capability catalog. Compare the same requests with vendor-prewired hooks and another relevant extension architecture. CEL can appear within either approach.

## Why

A working compiler does not establish whether catalog setup cost amortizes or avoids customer-specific vendor code. Invoice follow-up and weekly review repeat one call shape.

## In Scope

Record extension calls and dependencies, one-time host work for hooks/capabilities/types/contracts, and additional host code or operations for each customer. Include at least two materially different call or result shapes and identify requests the catalog cannot safely express.

## Out of Scope

Production ROI claims, implementing missing capabilities, or relaxing the one-write rule to make an example work.

## Done When

- At least two different customization shapes use one frozen catalog without customer-specific vendor code.
- The comparison records marginal host work, catalog reuse, one-time catalog cost and alternatives on the same requests.
- Unsupported requests and questions needing a prototype or real integration are explicit.

## Notes

The historical task-domain fixture is illustrative, not a certified catalog. Select a stronger second demonstration before committing demo implementation scope.
